# TSC Policies

The charter sets the TSC's baseline voting rules and leaves the rest for the TSC to define.
Each policy the TSC adopts is added to this folder as its own file, by pull request, with a
link to the minutes recording the vote.

Policies on contributing, roles, how Maintainers are added, and how TSC voting membership is
determined live in the organization's
[CONTRIBUTING.md](https://github.com/opendckit/.github/blob/main/CONTRIBUTING.md), as the
charter requires. The policies here cover how the TSC itself operates. The TSC election rules and any
company seat cap are defined in CONTRIBUTING.md, because they determine TSC voting
membership.

## Adopted

At the Nov 2, 2026 TSC meeting (minutes:
[2026-11-02 TSC Minutes](https://lf-networking.atlassian.net/wiki/spaces/OpenDCKit/pages/1534689285)),
the TSC set a 3-month inactivity threshold for Maintainers and TSC members, documented in
[CONTRIBUTING.md](https://github.com/opendckit/.github/blob/main/CONTRIBUTING.md) alongside
the other membership policies it governs.

The TSC also adopted, as process rather than as fixed membership rules:

- **Voting practice**: formal TSC votes and elections run as an
  [LFX Vote](https://app.lfx.dev/docs/votes). Quorum and tie-breaking follow the
  decision-making rules in CONTRIBUTING.md; how long a vote stays open and how abstentions
  are counted are still to be defined.
- **Chair election**: self-nomination followed by an LFX Vote, with a 1-year term matching
  the TSC's own election cycle. See the wiki's
  [Chair Election](https://lf-networking.atlassian.net/wiki/spaces/OpenDCKit/pages/1545699362)
  page for the full process. No election has been called yet, so the Chair seat is still
  unfilled.
- **Delegation of Maintainer approval**: a Maintainer may appoint a proxy if they plan to be
  out of the office, matching common practice elsewhere. The TSC keeps final sign-off
  approval of new Maintainers; that step is not delegated.
- **Working groups and SIGs**: the TSC agreed by consensus to stand up a Release Management
  working group and a Security working group. See the wiki's
  [Working Groups](https://lf-networking.atlassian.net/wiki/spaces/OpenDCKit/pages/1546321956)
  page and its two child pages for the draft shape of each. Who leads each group, the actual
  release cadence, and the vulnerability reporting channel (email vs. a security mailing
  list not yet created) are still open.

## Still to be defined

Until the TSC adopts a policy, nothing beyond the charter applies.

| Policy | What the TSC decides | Needed before |
| ------ | -------------------- | ------------- |
| Removal and reinstatement | Grounds for removal beyond inactivity, and how a member is reinstated short of an election | First TSC election |
| Conflicts of interest | Whether members recuse themselves where they or their employer have a direct commercial interest | No fixed deadline |
| Working group leads and chartering detail | Who leads Release Management and Security, and the full proposing/winding-down process for future working groups | First working group proposal |
| Release cadence and security reporting | Actual release cadence and sign-off, supported versions, and where a vulnerability report goes | First release |

The same list, with current status, is tracked on the
[Formation Status](https://lf-networking.atlassian.net/wiki/spaces/OpenDCKit/pages/1534132241)
wiki page.
